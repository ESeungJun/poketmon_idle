#주요 흐름

#1. 집중 → 포인트 → 레벨업·진화

sequenceDiagram
  participant U as 사용자
  participant T as PomodoroTimer
  participant S as useStore
  participant R as Rust(lib.rs)
  participant P as Pet 창
  U->>T: 집중 시작(1~120분)
  T->>S: petState = sleeping
  S->>R: set_store + 배회 멈춤
  R-->>P: state-sync → 잠자는 도트
  loop 시계 기준 1분마다
    T->>S: +2pt
  end
  T->>S: 완료 +75pt (중단 시 경과분만)
  S->>S: 레벨 계산(n² × 4), 기술 습득
  alt 진화 조건
    S->>S: petState = evolving (3초) → confirmEvolution
    S->>R: resize_pet_window(100/120/160)
  else
    S->>S: petState = happy (2초) → idle
  end
  R-->>P: state-sync, 배회 재개

#빌드·실행·배포

npm install
npm run dev          # Vite + Tauri 창 (Rust 필요). scripts/dev.sh는 기존 프로세스를 끄고 실행
npm run build        # 릴리스 빌드 (명시 요청 시에만, CLAUDE.md)
bash scripts/setup-hooks.sh          # pre-push 훅 설치(최초 1회)
bash scripts/new-feature.sh <이름>   # dev에서 feature 브랜치
cd pixel-art-source && node generate-preview.js   # 도트 미리보기 http://localhost:3131
  • 브랜치: master(프로덕션) · dev(통합) 모두 직접 push 금지. feature/* → dev PR → 릴리스 때 dev → master.
  • 코드 수정 뒤 PR 전 절차: 빌드 → 실행 확인 → 사용자 확인 → PR(CLAUDE.md).
  • feature 브랜치를 push하면 build.yml이 서명 없는 dmg·exe를 Actions 결과물로 남긴다(Rust 없는 Mac용).
  • 릴리스: package.json·src-tauri/Cargo.toml 버전을 올리고 v<버전> 태그 push → release.yml이 서명·공증된 universal dmg, NSIS exe, 업데이트 파일·서명·latest.json을 draft 릴리스로 올림 → Publish해야 자동 업데이트가 받는다.
  • PR 머지 뒤 ROADMAP과 timeline.html을 함께 갱신한다(프로젝트 메모리).
