# poketmon_idle 개선안

점검 기준: `3c30cf1` (v1.1.0), 2026-11-10. 저장소는 고치지 않았다. 빌드·검사는 임시 폴더 복사본에서 했다.

## 한 줄 정의

포모도로 집중 타이머를 쓰는 사람이, 집중하는 동안 잠들었다가 끝나면 포인트를 받아 자라는 도트 포켓몬을 바탕화면에 띄워 두고 키우는 데스크톱 펫. 비상업 팬 프로젝트.

## 컨셉·의도

- 목표 네 가지(`docs/기획서.md`): 집중하는 시간에 같이 자라는 펫 / 포켓몬 해 본 사람이 봐도 어색하지 않게 / 일하는 중 방해되지 않게 / 혼자서도 계속 굴러가게.
- 결정기록에서 읽히는 원칙: "이 앱은 집중이 먼저다". 잠든 모습이 곧 집중 중이라는 신호(무입력 자동 수면·휴식 타이머 제거), 배틀은 별도 창 없이 패널 탭에서만.
- 대상: 포모도로를 쓰는 macOS·Windows 사용자 중 포켓몬을 해 본 사람.
- 배포: GitHub Releases(서명·공증 universal dmg, NSIS), 자동 업데이트. 수익 없음. 권리 고지는 `README.md:413` 한 줄.

## 지금 있는 기능

ROADMAP Phase 1~5 가 전부 `[x]` 다. 코드와 대조한 결과:

- 펫 창(100/120/160px 투명·항상 위), 화면 오른쪽 1/3 바닥 배회, 드래그, 상태 4종(idle·happy·sleeping·evolving). 도트 19종 × 평소·수면.
- 집중 타이머 1~120분, 벽시계 기준. 분당 +2pt, 완료 +75pt.
- 레벨(누적 포인트 = n²×4), 진화, 성격·특성·IV·EV, 7세대 기술, TM.
- 야생 배틀(상성·상태이상 5종·능력치 단계·날씨), 포획, 보관함, 포켓몬센터, 상점.
- Electron 1.0.0 저장 데이터 가져오기, 자동 업데이트(미리 받고 누를 때 설치).

문서와 다른 곳:
- ROADMAP Phase 3 "집중 타이머 완료 시 패널 자동 오픈 + 배틀 탭 전환": 코드에 없다. `togglePanel` 호출은 펫 클릭 한 곳뿐이다(`src/App.jsx:42`). 완료 신호는 펫이 깨어나 2초간 하트를 띄우는 것이 전부다.
- 지니기 아이템 10종: 상점에서 150~500pt 에 팔고 효과 문구를 보여 주지만 배틀에 반영되지 않는다(README 에는 "구현 전"이라고 적혀 있고, 앱 안에는 표시가 없다).
- 배틀 승리 문구가 "+30 포인트" 고정이다(`src/components/Panel/Battle.jsx:285`). 실제 보상은 `10 + 레벨×1.5`(`src/data/battleEngine.js:394`).
- `mew` 가 종 데이터에 있지만(`src/data/pokemon.js:466`) 스타터·야생 풀 어디에도 없어 얻을 수 없다.

## 구조와 스택

- Tauri 2 + React 18 + Vite 5 + Zustand 4. 프런트 번들 하나를 창 두 개(pet·panel)가 `window.__POKE_VIEW__` 로 나눠 쓴다.
- `src-tauri/src/lib.rs`(714줄): 창, 트레이, `config.json` 저장소(허용 키 15개), 배회·드래그 루프(스레드 1개), 업데이트.
- `src/platform/tauri.js`: Tauri 명령을 예전 `window.electronAPI` 모양으로 감싼다.
- `src/store/useStore.js`(721줄): 상태·저장·창 간 동기화(`state-sync` 이벤트). 창마다 스토어가 따로 있고 변경분만 서로 보낸다.
- `src/data/battleEngine.js`(792줄): 배틀 순수 함수. `src/data/pokemon.js`: 종·기술 데이터.
- 타이머 상태는 `PomodoroTimer.jsx` 의 React ref 에만 있다.
- 외부 의존: 도트가 없는 종은 `raw.githubusercontent.com/PokeAPI/sprites` 에서 이미지를 불러온다(`pokemon.js:3-5`, CSP `tauri.conf.json`). 지금 해당 종은 얻을 수 없는 `mew` 뿐이다.
- `hooks/pre-push`: master·dev 에서 push 하면 막는 git 훅 하나. `scripts/setup-hooks.sh` 로 수동 설치.

### 발견한 문제

**🔴 1. 저장 파일이 깨지면 백업 없이 빈 데이터로 덮어쓴다**
- 지금 문제: `Store::load` 는 `config.json` 을 읽거나 파싱하지 못하면 "처음 실행"으로 보고 Electron 시절 파일이나 빈 맵으로 시작한 뒤 곧바로 `store.save()` 로 덮어쓴다(`src-tauri/src/lib.rs:54-75`). 파일이 없는 경우와 깨진 경우를 구분하지 않는다. 수십 일 키운 데이터가 한 번에 사라진다. 쓰기는 임시 파일 + rename 이라(`lib.rs:84-88`) 깨질 일은 드물지만, 손으로 편집했거나 디스크가 찼을 때 일어난다.
- 고치는 방법: 파일이 있는데 파싱에 실패하면 `config.json.corrupt-<시각>` 으로 옮기고 시작한다. 저장할 때 직전 파일을 `config.json.bak` 으로 하나 남긴다. 설정 탭에 "백업에서 되돌리기".
- 나아지는 점: 최악의 경우에도 직전 상태로 돌아간다.
- 예상 결과: 깨진 파일로 실행해도 원본이 남고, 백업에서 복구된다.

**🟠 2. 1분 타이머를 반복하면 분당 77pt 를 받는다**
- 지금 문제: 완료 보너스가 시간과 무관하게 +75pt 다(`src/store/useStore.js:278-290`). 최소 시간이 1분이라(`src/components/Panel/PomodoroTimer.jsx:5`) 1분 세션 한 번에 2 + 75 = 77pt. 25분 세션은 125pt(분당 5pt). 1차 진화(Lv.16, 1024pt)가 기획상 "하루 50분으로 4일"인데 1분 세션 14번이면 된다. 기록도 실제 시간과 상관없이 `durationMinutes: 25` 로 남는다(`useStore.js:283`).
- 고치는 방법: 보너스를 `Math.round(분 × 3)` 으로(25분이면 지금과 같은 75). 5분 미만은 보너스 없음. `addPomodoroSession(workMinutes)` 로 실제 시간을 넘겨 기록한다.
- 나아지는 점: 긴 집중이 짧은 반복보다 불리하지 않다.
- 예상 결과: 1분 세션 2pt, 25분 125pt, 50분 250pt.

**🟠 3. 배틀이 집중보다 열 배 넘게 빨리 레벨을 올린다**
- 지금 문제: 레벨은 `totalPointsEarned` 로 계산하고(`useStore.js:122-124`) 배틀 보상도 여기에 더해진다(`useStore.js:638`). 조우 비용 10pt 는 `points` 에서만 빠진다(`useStore.js:182-187`, `546`). Lv.16 에서 한 판에 약 34pt(`battleEngine.js:394`)이고 한 판은 수십 초다. 집중은 분당 5pt. 횟수 제한은 없다. 목표 1("집중하는 시간에 같이 자라는 펫")과 어긋난다. 한 판 소요 시간은 장면 0.5초 × 턴 수로 추정했고 직접 재지는 않았다.
- 고치는 방법: 레벨 경험치를 집중 포인트로만 올린다(새 키 `focusXp`, 기존 사용자는 `totalPointsEarned` 값으로 채움). 배틀 보상은 쓸 수 있는 `points` 만 준다. 조우는 집중 완료로 얻는 조우권으로 제한한다(기획 제안 1).
- 나아지는 점: 성장 속도가 집중 시간에 묶인다. 배틀은 포인트 벌이·포획 수단으로 남는다.
- 예상 결과: Lv.16 까지 집중 약 205분(기획서의 4일)이 실제로 지켜진다.

**🟠 4. 타이머가 패널 화면 메모리에만 있다**
- 지금 문제: 종료 시각·누적 시간·지급한 분이 `PomodoroTimer.jsx` 의 `useRef` 에만 있다(`PomodoroTimer.jsx:14-19`). 앱을 끄거나, 업데이트 설치로 재시작하거나(`lib.rs:650-654`), 패널 웹뷰가 다시 로드되면 진행 중 세션이 사라지고 펫은 `idle` 로 돌아간다. 완료 처리도 200ms `setInterval` 이 돌아야 일어난다(`PomodoroTimer.jsx:45-74`). 패널이 숨겨진 동안 웹뷰가 타이머를 늦추면 완료 보너스와 펫 깨우기가 패널을 다시 열 때까지 밀린다. 벽시계 방식이라 포인트는 나중에 맞춰지지만, 완료 시점 신호가 유일한 알림인 앱에서 그 신호가 늦는다. 숨은 웹뷰의 실제 스로틀 정도는 확인 못 했다.
- 고치는 방법: 타이머를 Rust 로 옮긴다. `start_focus(minutes)` 가 종료 시각을 `config.json` 에 저장하고, Rust 스레드가 분 지급·완료를 처리해 두 창에 이벤트를 보낸다. 시작할 때 저장된 종료 시각이 남아 있으면 이어서 한다.
- 나아지는 점: 재시작·업데이트·패널 상태와 무관하게 세션이 유지되고 제때 끝난다.
- 예상 결과: 집중 중 앱을 껐다 켜도 남은 시간이 이어진다.

**🟠 5. 끝났다는 걸 알기 어렵다**
- 지금 문제: 완료 때 일어나는 일은 펫이 깨어나 2초간 뛰는 것뿐이다(`useStore.js:165-179`). 소리·시스템 알림·패널 열기가 없다. 다른 창을 보고 있으면 놓친다. ROADMAP 은 패널 자동 오픈을 적어 두었지만 구현되지 않았다.
- 고치는 방법: 완료 때 시스템 알림 한 번(`tauri-plugin-notification`)과 펫 말풍선 "25분 끝! +125pt" 를 누를 때까지 유지. 패널 자동 오픈은 방해가 되므로 넣지 않고 ROADMAP 문구를 고친다.
- 나아지는 점: 집중이 끝난 시점을 놓치지 않는다.
- 예상 결과: 완료 후 펫 창에 결과가 남아 있다.

**🟠 6. 효과 없는 아이템을 효과 문구와 함께 판다**
- 지금 문제: 지니기 아이템 10종에 `effect: '기술 위력 ×1.3'` 같은 문구가 있고 150~500pt 다(`src/components/Shop/items.js:11-20`). `equippedTool` 은 상점·스탯 화면에서만 읽고(`Shop.jsx:14`, `PokemonStats.jsx:71`) `battleEngine.js` 는 쓰지 않는다. 상점은 "스탯 탭에서 효과 확인"이라고 안내한다(`Shop.jsx:82`).
- 고치는 방법: 구현 전까지 상점에서 "준비 중"으로 잠그거나, 수치 보정만 있는 6종(박식안경·저주의부적·독바늘·생명의구슬·먹다남은음식·조개껍질방울)부터 `processTurn` 에 반영한다.
- 나아지는 점: 포인트를 쓰고 아무 일도 없는 경험이 없어진다.
- 예상 결과: 장착한 아이템이 배틀 로그에 나타난다.

**🟠 7. 배포 형태와 저작권(사실 관계)**
- 지금 문제: 제품명이 "포켓몬키우기"(`tauri.conf.json`), 도트 19종은 공식 도트를 바탕으로 변환한 것(`docs/결정기록.md` 2026-03-12), 게임 화면 이미지 `public/PokeCenter.webp` 가 번들에 들어가고, 종·기술·도구 이름이 공식 한국어 명칭이다. 이 상태로 Developer ID 서명·공증 dmg 와 NSIS 를 공개 저장소 Releases 로 배포하고 자동 업데이트까지 한다. 고지는 `README.md:413` 한 줄이고 앱 안에는 없다. 저장소에 LICENSE 파일이 없어 코드 자체의 이용 조건도 정해져 있지 않다. 비상업이어도 권리자 허락이 생기는 것은 아니며, 삭제 요청이 오면 저장소·릴리스와 서명에 쓴 개발자 계정이 대상이 된다.
- 고치는 방법: 선택지를 나눠 사용자가 정한다. (a) 지금대로 두고 위험을 감수. (b) 바이너리 배포를 내리고 소스 빌드만 안내. (c) 제품명·아이콘에서 상표를 빼고, 캡처 이미지(`PokeCenter.webp`)를 직접 그린 것으로 바꾸고, 설정 탭에 고지문과 "비공식·비상업" 표기를 넣는다. 어느 쪽이든 후원·광고·유료 기능은 넣지 않는다.
- 나아지는 점: 위험의 크기를 알고 고른 상태가 된다.
- 예상 결과: 법적 판단은 확인 못 함. 이 문서는 사실만 적었다.

**🟡 8. 보관함 포켓몬이 전부 계정 레벨을 쓴다**
- 지금 문제: 레벨이 계정의 `totalPointsEarned` 하나에서 나온다(`battleEngine.js:215`). 보관함의 `level` 필드는 표시에만 쓰이고, 파트너로 바꾸면 Lv.3 구구도 바로 내 레벨이 된다(`useStore.js:448`, `454`). 교체할 때 `caughtAt` 이 새 파트너의 `petStats` 로 옮겨지지 않아(`useStore.js:470-480`) 다시 보관함에 넣으면 포획 시각이 그때 시각으로 바뀐다(`useStore.js:464`).
- 고치는 방법: 개체마다 `xp` 를 두고 집중 포인트는 현재 파트너에게 준다. `caughtAt` 을 `newPetStats` 에 포함한다.
- 나아지는 점: 잡은 포켓몬을 키울 이유가 생긴다.
- 예상 결과: 기획 제안 2 참고.

**🟡 9. 펫이 쉬지 않고 걷고, 배회 루프도 쉬지 않는다**
- 지금 문제: 배회 속도 하한이 0.3 이라(`lib.rs:283-285`) idle 인 동안 30fps 로 창 위치를 계속 바꾼다(`lib.rs:299-303`). 멈춰 있는 구간이 없다. 루프 스레드는 잠든 동안(배회 꺼짐)에도 33ms 마다 깬다(`lib.rs:234-255`). 창이 100~160px 이라 claude-bouncer 의 전체 화면 창보다 훨씬 가볍겠지만, 시야 구석에서 항상 움직이는 것은 목표 3과 맞지 않는다.
- 고치는 방법: "걷기 5~15초 → 서 있기 20~60초" 구간을 둔다. 배회가 꺼져 있으면 스레드를 `Condvar` 로 재운다.
- 나아지는 점: 창 이동과 깨어남이 대부분 사라지고 펫이 덜 산만하다.
- 예상 결과: 유휴 창 이동 초당 30회 → 평균 5회 이하. CPU 는 재지 못했다.

**🟡 10. 저장 구조에 버전이 없고 키마다 파일 전체를 다시 쓴다**
- 지금 문제: `set_store` 한 번에 전체를 pretty JSON 으로 직렬화해 쓰고 rename 한다(`lib.rs:375-381`, `78-89`). `addPoints` 한 번에 2~3회, 파트너 교체는 5회(`useStore.js:494-498`) 연속으로 일어나 중간에 꺼지면 종과 스탯이 어긋난 상태가 남을 수 있다. 스키마 버전 키가 없어 3번·8번 같은 구조 변경 때 옛 데이터를 구분할 방법이 `validateStore` 의 타입 검사뿐이다(`useStore.js:48-81`). `caughtPokemon` 은 상한이 없다.

DEVLOG 의 버그(울부짖기 멈춤, 아픔나누기 HP 0)는 전부 이 파일이다. `hooks/pre-push` 는 `scripts/setup-hooks.sh` 를 손으로 돌려야 설치되고(이번 클론의 `.git/hooks` 에는 없다), 현재 브랜치 이름만 본다(`hooks/pre-push:2-4`). `git push origin HEAD:master` 는 통과하고, dev 에 서서 다른 브랜치를 push 하면 막힌다. CI(`build.yml`)는 `feature/**` push 에서 빌드만 한다.

펫 동작:
- 잠든 모습 = 집중 중이라는 규칙은 분명하고 좋다. 지켜야 한다.
- idle 에서 쉬지 않고 좌우로 걷는다(점검 9). 서 있는 시간을 길게.

## 성능 제안

- 프런트 번들 449kB(gzip 100kB)는 로컬 로드라 문제가 아니다. 다만 펫 창도 패널 코드 전체(배틀 엔진·상점)를 싣는다. 펫 화면을 별도 진입점으로 나누면 상주하는 펫 웹뷰의 메모리가 준다(감소폭 미측정).
- 배회 루프: 점검 9. 서 있는 구간 도입과 `Condvar` 대기.
- `drawPokemon` 은 프레임마다 칸 수만큼 `fillRect` 한다(`pokemonDraw.js:5-20`). idle 3fps, 최대 32×29 칸이라 부담은 작다. 수면 애니메이션은 네 프레임이 전부 같은 그림인데 2fps 로 다시 그린다(`pokemonDraw.js:60-68`). 프레임 1개, 타이머 없음으로 바꾼다.
- 저장: 점검 10. 한 동작에 한 번 쓰기.
- 타이머 `setInterval` 200ms(`PomodoroTimer.jsx:45`)는 Rust 타이머로 옮기면 1초 이벤트로 준다.
